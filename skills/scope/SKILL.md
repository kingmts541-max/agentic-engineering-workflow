# Scope

Define the problem and desired outcome—not the implementation. Record acceptance criteria, in-scope work, non-goals, constraints, affected areas, risks, unknowns, assumptions, and verification plan. Use `templates/scope.md` when useful.

Keep scope as a living plan in `docs/scope/` for multi-step work. Include a suitable depth: **Prototype**, **Alpha**, **Beta**, or **GA** (see `AGENTIC_WORKFLOW.md`); these are defaults, not rigid stages.

Ask before resolving ambiguity that materially changes product behavior, security, data semantics, or compatibility. For existing projects, audit before scoping the next slice; for greenfield projects, scope before scaffolding.
