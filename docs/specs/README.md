# Spec state

Store non-trivial implementation/design specs here. Use `../../templates/spec.md` as a starting point and adapt to project conventions.

A spec should have numbered, observable acceptance criteria and explicit decision status. Mark consequential decisions Proposed until approved. Update the status as work progresses: Proposed → Approved → Implemented → Verified. Use Superseded when replaced. An explicitly authorized but unresolved assumption must remain labelled Assumed until ratified. Do not treat a Proposed spec as implementation authorization.
